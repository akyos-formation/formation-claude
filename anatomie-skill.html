Anatomie d’un skill

Un skill est un dossier qui contient une méthode de travail. Claude l’ouvre quand votre demande y correspond. L’endroit où vous le rangez décide où il fonctionne.

Ce qu’est un skill

Un skill réunit des instructions et, si besoin, des modèles, des exemples ou des scripts. Claude connaît en permanence son nom et sa description, et n’ouvre le reste que lorsque la tâche le demande. Il fonctionne comme une fiche de procédure dans un classeur : Claude lit les étiquettes et ne sort que la fiche utile.

Quand en créer un ? Dès que vous recollez les mêmes consignes, la même checklist ou la même procédure d’un échange à l’autre.

        Comment le déclencher

        Le même skill s’appelle de quatre façons. La description décide du déclenchement automatique, les autres modes vous laissent la main.

        Laisser faire Claude

        Rédige un post LinkedIn sur notre session de novembre.

        Partout où le skill est disponible. C’est le mode par défaut.

        Le nommer

        Utilise mon skill post-linkedin-marque pour ce brief.

        Partout. Utile si Claude ne le prend pas de lui-même.

        Taper la commande

        /post-linkedin-marque session de novembre

        Claude Code, add-ins Microsoft 365, tâches planifiées Cowork, et skills de plugin dans le chat et Cowork.

        Le planifier

        Chaque lundi matin, fais la veille IA avec le skill veille-sectorielle.

        Tâche planifiée ou routine. Le prompt de la tâche appelle le skill, sans vous.

        Qui a la main ?

        Dans Claude Code, deux champs de SKILL.md réservent le déclenchement.

        Ces deux champs sont propres à Claude Code. Un skill qui les contient est refusé au téléversement sur Claude.

        Si Claude ne l’utilise pas

        • Le skill est activé dans Personnaliser > Compétences.
        • L’exécution de code et la création de fichiers sont activées.
        • La description dit ce que fait le skill et quand l’utiliser.
        • Votre demande le nomme explicitement.
        • Dans Claude Code, il apparaît quand vous tapez /skills.

        Où il vit, où il fonctionne

        Un skill communautaire ou personnalisé peut finir à plusieurs endroits. Suivez le chemin de gauche à droite : l’origine ne compte que pour la confiance, l’emplacement fixe les contextes atteints. Cliquez sur un élément, ou partez d’un besoin.

        « Skill not found » dans une routine

        Cowork et le cloud ne lisent pas ~/.claude/skills/ sur votre machine. Activez le skill sur votre compte, ou commitez-le dans le dépôt pour une session cloud.

        Téléversement refusé

        Sur Claude, l’en-tête n’accepte que name, description, license, compatibility, metadata et allowed-tools. Tout autre champ provoque une erreur.

        Modifications perdues

        ~/.claude/skills/synced/ est une copie de votre compte, dans un seul sens. Modifiez le skill sur Claude : ce que vous changez dans ce dossier n’est pas renvoyé et peut être écrasé.

        Deux skills du même nom

        Entreprise passe avant personnel, personnel avant projet. Un skill de plugin garde son préfixe, /plugin:skill, et n’entre pas en conflit.

        L’API Claude a son propre circuit : les skills y sont envoyés avec /v1/skills et partagés dans le workspace. Ils ne figurent pas sur ce schéma.

        Vérifié le 5 novembre 2026 dans la documentation officielle. Ces fonctions évoluent vite : contrôlez les chemins et les libellés avant chaque session.
